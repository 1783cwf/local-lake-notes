# 本地笔记 AI 助手

## Summary

第一版 AI 助手面向当前文档、选中文本、写作生成和多维表格辅助，帮助用户在明确授权范围内总结、改写、整理、生成和结构化笔记内容。全知识库问答、跨文档引用、相似/重复/冲突检测、知识地图和专题汇总页作为后续阶段，不进入第一版。

---

## Problem Frame

Local Lake Notes 已经支持本地知识库、`.lake` 文档、表格、多维表格、资源存储和导出。用户在日常笔记中会频繁遇到整理成本：长文需要摘要和结构建议，零散内容需要归纳成文章，会议纪要需要提取任务，技术笔记需要转成更适合分享或沉淀的形式。

这些工作目前需要用户手动完成，尤其在当前文档已经承载大量内容时，整理、重写、拆分和结构化输出会打断写作流。第一版 AI 能力应优先降低当前文档和明确选中内容的处理成本，而不是提前扩展到全知识库检索。

---

## Actors

- A1. 个人用户：在本地知识库中编辑文档、整理笔记、生成内容，并决定是否接受 AI 输出。
- A2. AI 助手：基于用户明确选择的当前文档、选中文本或表格上下文生成建议和草稿。
- A3. 本地笔记 App：提供文档内容、选择范围、预览确认和最终写入能力。
- A4. 多维表格：承载字段、记录、状态、标签、任务和看板等结构化信息。

---

## Key Flows

- F1. 当前文档辅助
  - **Trigger:** 用户打开 `.lake` 文档并调用 AI 助手。
  - **Actors:** A1, A2, A3
  - **Steps:** 用户选择动作；App 将当前文档作为上下文；AI 返回总结、问答结果、标题、摘要、待办或结构建议；用户查看结果；如需写入，用户确认后再应用。
  - **Outcome:** 用户获得当前文档级别的整理结果，文档不会被自动改写。
  - **Covered by:** R1, R2, R3, R4, R18, R20

- F2. 选中文本改写
  - **Trigger:** 用户在 `.lake` 文档中选中一段内容并调用改写类动作。
  - **Actors:** A1, A2, A3
  - **Steps:** 用户选择润色、改写、扩写或压缩；AI 基于选中文本生成候选结果；App 展示替换预览；用户确认后替换或插入。
  - **Outcome:** 选中文本被用户确认后的 AI 结果更新，未确认时原文保持不变。
  - **Covered by:** R5, R6, R18

- F3. 写作工作流辅助
  - **Trigger:** 用户需要从提纲、零散笔记或现有技术笔记生成更完整的文档。
  - **Actors:** A1, A2, A3
  - **Steps:** 用户选择生成目标；AI 输出初稿、文章、结构建议、教程、README、发布说明或拆分方案；App 展示预览；用户确认后写入当前文档或创建新文档。
  - **Outcome:** 用户获得可继续编辑的写作成果，涉及新建或拆分文档时必须经过确认。
  - **Covered by:** R7, R8, R9, R10, R11, R18

- F4. 多维表格辅助
  - **Trigger:** 用户在多维表格或会议纪要场景中调用 AI 助手。
  - **Actors:** A1, A2, A3, A4
  - **Steps:** 用户选择字段生成、任务提取、表格摘要、标签/状态建议或会议纪要转任务看板；AI 生成结构化候选结果；App 展示字段、记录或看板变更预览；用户确认后写入。
  - **Outcome:** 多维表格获得用户确认后的结构化内容，AI 不直接静默修改表格。
  - **Covered by:** R12, R13, R14, R15, R18

## Requirements

**当前文档助手**

- R1. AI 助手必须支持对当前 `.lake` 文档生成摘要、标题建议、待办列表和会议纪要。
- R2. AI 助手必须支持基于当前 `.lake` 文档进行问答，回答范围默认限定在当前文档。
- R3. AI 助手必须支持把散乱内容整理为带小标题的结构化内容。
- R4. AI 助手必须支持在导出前生成更适合 Markdown 或 HTML 阅读的文档版本，但不能改变 `.lake` 主文档，除非用户确认写入。

**选中文本处理**

- R5. AI 助手必须支持对用户选中文本执行改写、润色、扩写和压缩。
- R6. 选中文本类操作必须展示原文与候选结果的预览，用户确认后才能替换、追加或插入。

**写作工作流助手**

- R7. AI 助手必须支持从提纲生成初稿，并允许用户继续编辑生成结果。
- R8. AI 助手必须支持从零散笔记生成文章，输出应优先保持可读结构，而不是只拼接原始片段。
- R9. AI 助手必须支持给长文生成结构建议，包括章节拆分、标题层级和内容组织建议。
- R10. AI 助手必须支持把技术笔记转换为教程、README 或发布说明等写作形式。
- R11. AI 助手必须支持把长文档拆分为多个子文档的候选方案；拆分涉及新建文档时必须先预览目标文档清单和内容摘要，并由用户确认。

**多维表格/表格助手**

- R12. AI 助手必须支持根据用户描述生成多维表格字段候选方案。
- R13. AI 助手必须支持从当前文档或用户提供内容中提取任务、日期、状态、标签和优先级建议。
- R14. AI 助手必须支持对表格数据生成摘要，并支持根据记录正文建议状态或标签。
- R15. AI 助手必须支持把会议纪要转换为任务看板候选内容。

**安全边界和确认机制**

- R16. 第一版 AI 助手不得建立全知识库索引，不得默认读取整个知识库。
- R17. AI 助手默认只能处理当前文档、用户选中文本、当前表格或用户明确提供的内容。
- R18. 所有写入、替换、新建文档、拆分文档和表格变更都必须先预览，再由用户确认。
- R19. AI 助手不得后台自动修改笔记、表格、资源或知识库结构。
- R20. 当 AI 输出引用原文内容或生成结构化变更时，App 必须让用户能判断输出基于哪个输入范围。

**模型协议**

- R21. 第一版 AI 助手必须同时支持 Anthropic Messages API 和 OpenAI Responses API 两种标准模型协议；配置层只提供这两种协议选项，不支持其他 Provider 或非标准兼容协议。
- R22. AI 模型设置必须支持多个模型配置 profile。每个 profile 可配置名称、协议类型、Base URL 和 API Key；配置 Base URL 与 API Key 后，用户可以按所选标准协议获取模型列表，把模型加入本地可用模型列表，并选择一个模型作为当前启用模型。
- R23. AI 模型设置必须支持给模型标注能力类型，类型仅包括：视觉、联网、推理、工具、重排、嵌入。第一版暂不按“是否支持结构化输出”过滤模型。
- R24. 当模型标注为视觉能力时，AI 助手可使用图片和文本作为输入；第一版暂不接入视频、音频、文件等其他输入形态。

## Acceptance Examples

- AE1. **Covers R1, R2, R18.** Given 用户打开一篇 `.lake` 文档，when 用户选择“总结当前文档”，then App 展示摘要预览，且不会自动写入文档。
- AE2. **Covers R5, R6, R18.** Given 用户选中一段文本，when 用户选择“润色”，then App 展示原文和润色结果，用户确认后才替换选中文本。
- AE3. **Covers R7, R8.** Given 用户在当前文档中提供提纲或零散笔记，when 用户选择生成初稿或文章，then AI 输出带标题和段落结构的可编辑草稿。
- AE4. **Covers R10.** Given 当前文档是一篇技术笔记，when 用户选择转换为 README，then AI 输出 README 风格的候选内容，并保留用户确认入口。
- AE5. **Covers R11, R18.** Given 当前文档很长，when 用户选择拆分文档，then App 先展示拟创建的子文档标题、摘要和内容预览，用户确认后才创建。
- AE6. **Covers R12, R15, R18.** Given 用户提供会议纪要，when 用户选择转任务看板，then AI 输出字段和任务记录候选，用户确认后才写入多维表格。
- AE7. **Covers R16, R17, R19.** Given 用户没有选择全库范围，when 用户进行当前文档问答，then AI 不读取其他文档，也不会后台修改任何笔记。
- AE8. **Covers R21, R22.** Given 用户新增一个模型配置 profile 并填写 Base URL 与 API Key，when 用户点击获取模型列表，then App 按该 profile 的标准协议拉取可用模型，用户可以把模型加入列表并选择其中一个作为当前启用模型。
- AE9. **Covers R23, R24.** Given 用户给某个模型标注视觉能力，when 用户在 AI 助手中使用该模型，then App 可提供文本和图片输入入口，且不会在第一版提供视频、音频、文件等输入入口。

---

## Success Criteria

- 用户能在当前文档内完成总结、问答、改写、整理和写作生成，不需要离开本地笔记工作流。
- 用户能把会议纪要或零散内容转换为可确认的文档或多维表格候选结果。
- 所有 AI 写入行为都以预览和确认作为边界，避免误改本地笔记。
- 下游实现计划可以直接围绕当前文档助手、写作工作流助手、多维表格助手和确认机制拆分任务。

---

## Scope Boundaries

- 第一版不做全知识库问答。
- 第一版不做跨文档引用相关笔记。
- 第一版不做相似文档、重复内容或冲突结论检测。
- 第一版不做主题知识地图。
- 第一版不做根据已有全库笔记生成专题汇总页。
- 第一版不做后台自动扫描、自动改写或自动整理知识库。
- 第一版不把 AI 助手定位为通用聊天机器人。
- 第一版不做 OpenAI-compatible Chat Completions、Anthropic-compatible 变体、本地模型专属适配或其他 Provider 配置；Base URL 只作为两种标准协议的服务地址。
- 第一版暂不接入视频、音频、文件等输入形态；视觉能力表示模型可使用文本和图片输入。

---

## Key Decisions

- 当前文档优先：先服务用户正在编辑和明确选中的内容，降低隐私、性能和误读范围风险。
- 写入前确认：AI 可以生成候选结果，但不能绕过用户确认直接修改本地数据。
- 多维表格进入第一版：任务提取、字段建议和会议纪要转看板与现有多维表格能力结合紧密，优先级高于全库问答。
- 全库能力后置：知识库问答和跨文档分析需要索引、引用溯源和结果验证机制，放到后续阶段。
- 双协议支持：第一版模型接入必须覆盖 Anthropic Messages API 和 OpenAI Responses API 两种标准协议，配置层只允许用户在这两种协议之间选择。
- 多模型配置：配置层支持多个模型 profile，每个 profile 保存协议、Base URL、API Key 和已添加模型；AI 助手始终使用当前启用模型。
- 模型类型：模型能力类型只维护视觉、联网、推理、工具、重排、嵌入六类；第一版不把结构化输出能力作为独立模型类型或过滤条件。

---

## Dependencies / Assumptions

- 假设用户接受第一版 AI 能力需要手动触发，不要求后台常驻自动运行。
- 假设第一版 AI 输出都可通过预览面板或等价确认界面完成确认。
- 假设当前 `.lake` 文档内容可以被转换为适合 AI 处理的文本上下文；具体转换方式留给实现计划确定。
- 假设多维表格写入前可以展示字段、记录和看板变更预览；具体交互形式留给实现计划确定。
